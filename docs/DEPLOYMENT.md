# Production-развёртывание: Docker, HTTPS и VPS

Реализованы конфигурация Compose, production-сборка React, Caddy, managed migrations,
secret files и backup/restore. Результаты фактических проверок — AUDIT.md, технические
команды — DOCKER_OPERATIONS.md, модель защиты/предложение retention — PRODUCTION_SECURITY.md.
Публичное развёртывание требует отдельного разрешения владельца проекта.

## Архитектура

```text
HTTPS/WSS :443 → Caddy + собранный React
                    ↓ private Docker network
                один процесс FastAPI :8000
                    ↓
                PostgreSQL18 + отдельный том cases
```

Постоянные тома: database, cases, caddy_data, caddy_config. API и PostgreSQL не имеют
опубликованных портов. Caddy — единственная точка входа, сохраняющая исходный Host/Origin
и передающая доверенные proxy headers. API доверяет только указанному IP Caddy.
В production нет Vite, Redis, второго API-процесса или автоматических миграций при restart.
Служебные cases-init/migrate запускаются явно для подготовки прав тома и схемы.

## Требования к VPS

Практический стартовый ориентир — Linux x86_64/arm64, 2vCPU, 4GiB RAM, SSD от40GiB,
Docker Engine с Compose v2, домен и отдельное место для зашифрованных резервных копий.
Это рекомендация ресурсов, не подтверждённая нагрузочная ёмкость; свободное место зависит
от числа комнат, импортов и частоты backup. Для сборки образов нужен доступ к npm/PyPI
и реестрам Docker; build cache тоже занимает диск.

Оператор готовит SSH-доступ, обновления ОС и firewall. Публичные TCP80/443 нужны Caddy,
PostgreSQL5432 и API8000 не открываются. SSH разрешается только администратору.
Если задаётся AAAA, IPv6 должен действительно работать; неверная DNS-запись мешает TLS.
Docker-порты имеют собственные правила firewall: проверяйте результат извне, а не только
настройку UFW. На этом этапе никаких VPS/DNS/firewall изменений не выполнялось.

## Первый публичный запуск — только после отдельного разрешения

1. Подготовить VPS, Docker/Compose, домен A/AAAA, доступность80/443. Выбрать release
   исходного кода и сохранить его версию вместе с backup; один архив БД не заменяет код.
2. Скопировать проект на сервер. Не переносить текущую локальную `.env` или тестовую БД.
3. Сгенерировать отдельные production-секреты без вывода в терминал:

```sh
python3 infra/ops.py --env-file /opt/detective/private/production.env \
  --project detective init --domain detective.YOUR-DOMAIN --email YOUR-EMAIL
```

Замените домен/email реальными значениями перед запуском. Init отказывается заменять
существующее окружение. Файл содержит публичную конфигурацию; pepper/DB credentials
хранятся отдельно в приватном sibling-каталоге. Сохраните их для восстановления сессий.
Не используйте `docker compose config` без `--quiet` в общих логах/публикациях.

4. Собрать и запустить контролируемо:

```sh
python3 infra/ops.py --env-file /opt/detective/private/production.env \
  --project detective start
```

Команда собирает образы, останавливает API/proxy перед миграцией, ждёт БД, готовит
cases volume, применяет Alembic head, запускает API/proxy с health checks. Ошибка
миграции не должна сопровождаться запуском несовместимого API. Скрипт не управляет DNS
и не создаёт внешние ресурсы; Caddy получает сертификат только при реальном публичном
запуске и корректном домене.

5. Проверить redirect HTTP→HTTPS, сертификат, `/health/ready`, создание комнаты,
   два отдельных браузерных профиля, Secure/HttpOnly/SameSite=Lax `__Host-` cookie,
   WSS, приватность изображений, F5/reconnect. Затем проверить backup/restore отдельно.
6. Установить полноценное оригинальное дело и провести человеческую редакторскую
   проверку. В репозитории есть только учебное demo; оно не является релизным делом.
7. Только после технических проверок согласовать полную партию друзей на VPS — этап8.

## Обновление и откат

До обновления сделайте backup и убедитесь, что проверяли его восстановление. Сохраните
текущий release/образы/секреты. Обновите код и зафиксированный IMAGE_TAG; затем выполните
контролируемый start. Миграции не выполняются при простом restart контейнера.

При ошибке миграции оставьте трафик закрытым и оцените совместимость схемы. Автоматического
`alembic downgrade` нет. В частности, c6e20a4f9137 не откатывается с существующими
комнатными импортами: превращать их в публичные/удалять партии недопустимо.
Восстановление старого релиза выполняется из согласованного backup в новое пустое
окружение; рабочие тома не удаляются ради отката. Подробные команды — DOCKER_OPERATIONS.md.

## Backup, retention и границы выпуска

Backup включает pg_dump, cases, TLS-данные Caddy, pepper и DB secrets; API/proxy на время
снимка останавливаются. Каталог backup содержит секреты и закрытые игровые данные:
шифруйте его перед переносом, храните ключ отдельно и проверяйте восстановление.
Не публикуйте его в Git, логах, облачных ссылках общего доступа или CI artifacts.

Retention пока только предложен в PRODUCTION_SECURITY.md. Автоматического удаления
комнат, партий, сессий или импортов нет до утверждения политики и dry-run реализации.
Готовность публичного домена, релизное дело и живая партия остаются отдельными воротами.
