# SCENARIO_FORMAT — единый пакет детективного дела

Версия: `1.0.0`. Расширение: `.detective` — **обычный ZIP-архив**, переименованный в `.detective`, кодировка JSON UTF-8. Резервировать формат на дальнейшие версии; не принимать неизвестный major-version.

## 1. Содержание архива

```text
case-name.detective  (ZIP)
├── case.json           # обязательный файл, канонический источник структуры
└── assets/             # необязательные PNG/JPEG/WebP
    ├── clue-03.webp
    └── floorplan.png
```

Не использовать несколько взаимоисключающих описаний сценария (`cards.json` и `case.json` одновременно). Для MVP единственный обязательный источник — `case.json`.

## 2. Модель истории (игровая структура)

1. **Завязка (`intro`)**: текст общей ситуации и цель расследования. Всем известна заранее.
2. **Стартовая карточка (`start_card`)**: особая общая карта, открыта до начала ходов; не входит в раздачу и штрафы.
3. **Колода (`play_cards`)**: перемешиваемые игровые карты — показания, документы, предметы, свидетельства, фотографии, слухи, ложные следы. Карты независимы от конкретного игрока.
4. **Разрешённые к произнесению фрагменты**: отдельные сегменты текста `shareable: "highlight"` или `"clip"` — можно оглашать из руки до публикации. Весь остальной текст секретен.
5. **Контрольные вопросы (`questions`)**: 3–6 вопросов; у каждого 2–5 вариантов, **ровно один** правильный. UI показывает варианты, без свободных ответов.
6. **Разгадка (`solution`)**: исчерпывающее объяснение того, что произошло, когда, кто участвовал, почему; временная шкала и ссылки на улики.
7. **Оценка (`scoring`)**: 2 очка за правильный ответ; минус 1 за открытую нерелевантную игровую карту; минимум 6 карт в сбросе, иначе минус 3 за каждую недостающую.
8. **Авторские пометки (`role`, `logic_notes`, `supports_questions`, `correct_option_id` и др.)**: необходимы для валидации, проверки и отчёта; **не отправлять игрокам до результатов**, кроме ключа вопроса только ведущему в REVIEW после фиксации ответов.

Не копировать чужие истории, собственные тексты и медиа обязательны.

## 3. Поля `case.json`

| Путь | Тип | Смысл |
| --- | --- | --- |
| `format` | literal `detective-case` | маркер формата |
| `format_version` | literal `1.0.0` | версия контракта |
| `id` | строка-slug | уникальный ID истории (например, `missing-letter-2026`) |
| `meta` | объект | название, автор, краткое без спойлеров описание, сложность, длительность, язык, число игроков, оригинальность |
| `intro.text`, `intro.public_goal` | строки | публичная вводная и цель |
| `start_card` | объект | публичная стартовая карточка (ID, заголовок, блоки) |
| `play_cards` | массив | игровые карточки с ID, типом, блоками, ролью и авторскими пометками |
| `questions` | массив | задания, варианты и закрытый ключ |
| `solution` | объект | истинная история и хронология |
| `scoring` | объект | серверные значения весов (для стандартного MVP фиксированы) |
| `assets` | массив | декларации существующих файлов в архиве (может быть пуст) |

### Блоки карточки

`blocks` — массив в порядке показа:

```json
{"type":"text","segments":[
  {"text":"Свидетель увидел "},
  {"text":"красный фургон","shareable":"highlight"},
  {"text":" возле склада в 21:40."}
]}
```

Сегмент без `shareable` приватен до публикации. Значение `"clip"` означает отрывок с отметкой «скрепка»; `"highlight"` — выделенный фрагмент. Оба разрешены для устного сообщения, но не становятся публичной картой автоматически.

Изображение:

```json
{"type":"image","asset_id":"photo-01","caption":"Снимок склада"}
```

`asset_id` обязан ссылаться на существующий элемент `assets`. Если ИИ не умеет создавать реальные медиафайлы, не добавлять фиктивные `assets` или `image` блоки; дело обязано оставаться полноценно играбельным по тексту.

### Роль карты

- `essential` — ключевой вывод или факт, необходимый для раскрытия;
- `supporting` — подтверждение, контекст, связка;
- `red_herring` — ложный след или нерелевантная деталь: публикация даёт штраф `−1`.

`logic_notes` — закрытое пояснение, **почему** роль присвоена, а `supports_questions` — список связанных вопросов. Для `red_herring` `logic_notes` обязан объяснять, почему улика не нужна, но не полагаться на ложь без возможности её распознать.

## 4. Рекомендуемый размер и баланс

В настольном исходнике используется комплект из 37 физических карт, часть из которых служит финальным вопросам/ответам. Онлайн-пакет **не обязан** буквально моделировать эти физические служебные карты. Для нового авторского дела предлагается стандартный размер **27 игровых карт + 1 стартовая + 4 вопроса**, а разгадка хранится отдельно в JSON. Система допускает 6–64 игровых карт.

Для 27-карточного дела рекомендовано минимум 8 осмысленных `red_herring`, не менее 5 существенных улик; иначе штраф за недостаток сброса превращается в бессмысленный выбор. Нельзя выдавать метки `role` игроку.

## 5. Строгие инварианты импортёра

**Синтаксис/структура (JSON Schema):** `schema/detective-case.schema.json`.

**Дополнительная семантическая валидация в коде:**

- `id` карточек, вопросов, опций и ассетов уникальны в своём пространстве; стартовая карта не дублирует игровую;
- все ссылки `supports_questions`, `evidence_card_ids`, `asset_id` существуют;
- `correct_option_id` совпадает **ровно с одним** `options[].id` своего вопроса;
- минимум 6 игровых карточек с ролью `red_herring` для стандартного `minimum_discards=6`;
- количество карт позволяет выдать стартовую руку при заявленном `max_players` (для 8 игроков не менее 16 игровых карт); если меньше, отклонять пакет; автор должен снизить `meta.max_players` до допустимого;
- `scoring` строго соответствует контракту MVP (2, 1, 6, 3), пока не введено новое семейство правил;
- справедливость вопросов: каждый `evidence_card_ids` содержит минимум две разные существующие карточки, улики достаточны для единственного ответа, разгадка не противоречит им;
- основная логика дела остаётся разрешимой по опубликованным картам, если команда выбирает разумную стратегию отбраковки ложных следов; секретные авторские пометки не являются единственным источником разгадки;
- ни один медиа-путь не выходит за `assets/` и каждый файл реально включён в ZIP; нет внешних обязательных URL;
- полные тексты, подсказки и изображения пригодны для чтения без дополнительных приложений; архив не содержит JS, SVG, HTML, выполняемые файлы, вложенные архивы;
- допустимы только оригинальные тексты/медиа, заявленные автором.

## 6. Секреты и проекция состояния

До завершения разыгрывания сервер отдаёт каждому игроку только свои карточки и публичные карточки. Никому до фиксации ответов нельзя отдавать `correct_option_id`, `explanation`, `solution`, `role`, `logic_notes`, `supports_questions`. В `ANSWERING` игроки видят `questions[].id`, `text`, `options[].id`, `text`; после перехода в `REVIEW` только ведущему доступны `correct_option_id`, `explanation`, `evidence_card_ids`. Командный выбор заблокирован, `solution` и роли карт по-прежнему закрыты. В `RESULTS`/`FINISHED` всем участникам показываются ключ, разгадка и результат.

Пакет физически хранится на сервере, **не** скачивается игроком целиком по ходу партии.

## 7. Создание и экспорт

Если ИИ способен создавать файлы, он обязан сформировать валидный `case.json`, включить реальные медиа при наличии, упаковать ZIP и назвать его `<id>.detective`. Если ИИ отвечает только текстом — он должен вернуть **один полный JSON `case.json`** в кодовом блоке; пользователь сохраняет его и упаковывает в ZIP, либо разработчик делает это автоматически в интерфейсе. Никаких условных `TODO`, `...`, «здесь будет 27 карт» внутри JSON.

Для подготовки дела без знаний нашей переписки передавайте модели `CASE_GENERATION_PROMPT.md` + этот документ + JSON Schema. Сам промпт дублирует основные ограничения и остаётся пригодным отдельно.


## 8. Уточнение HTTP-импорта этапа 6

Формат 1.0.0, схема, правила ZIP/медиа и валидатор не меняются. HTTP принимает готовый
пакет в единственном multipart-поле file, а не сырой JSON. Клиентские filename/MIME
не являются источником истины; сервер проверяет содержимое.

При импорте сервер создаёт комнатный непрозрачный ID записи каталога. Он отличается
от авторского id внутри case.json; внутренний manifest.id не переписывается. Повтор
тех же байтов безопасен, другое содержимое под прежним авторским ID в той же комнате
не перезаписывает дело. Для переработанной версии используйте новый авторский ID.
Дело не становится публичной библиотекой. Уже запущенную партию заменить нельзя.
Транспортные лимиты/ресурсы — IMPORT_API.md; подготовка и загрузка — IMPORT_GUIDE.md.
