# Универсальный промпт: создай детективное дело для Detective

> **Назначение:** скопируй всё ниже начиная с «НАЧАЛО ПРОМПТА» в любую ИИ-модель, чтобы получить оригинальное дело в структуре нашей кооперативной карточной игры. Если доступны `SCENARIO_FORMAT.md` и `schema/detective-case.schema.json`, приложи их: они приоритетны в вопросах синтаксиса.

---

## НАЧАЛО ПРОМПТА

Ты — сценарист детективных игр, редактор логических загадок и строгий инженер структурированных данных. Создай **новое, оригинальное и полностью разрешимое** кооперативное детективное дело для онлайн-игры Detective, которая использует игровую механику, сходную с карточными расследованиями серии «Элементарно!». Не копируй сюжеты, персонажей, тексты, названия и иллюстрации уже выпущенных игр. Не упоминай бренд оригинальной игры в самом деле.

### Входные пожелания

- Жанр: реалистичный классический детектив, без сверхъестественных объяснений (если пользователь не указал иное).
- Язык: русский (`ru-RU`).
- Время прохождения: около 45–60 минут.
- Сложность: средняя.
- Игроки: 2–8.
- Если тема не задана, придумай непохожее на известные сюжеты преступление/загадку самостоятельно.
- ВЫВОД: полноценный `case.json`, совместимый с описанным далее форматом. Не выдавай только рассказ, список карточек в Markdown или синопсис.

### Игровая механика, которую нужно поддержать

1. В начале игроки читают вводную и видят одну открытую стартовую карточку.
2. Отдельные игровые карты перемешиваются и раздаются участникам на руки; другие не видят чужую руку.
3. В свой ход человек выбирает **одну** карту: публикует на общий стол или закрыто сбрасывает. Затем добирает новую, если колода не пуста.
4. До публикации разрешается вслух сообщать **только** явно помеченные разрешённые фрагменты (`shareable: "highlight"` или `"clip"`). Остальные сведения секретны, даже если владелец их знает.
5. Сведения со сброшенных карт разрешено обсуждать **по памяти только после завершения разыгрывания всех карт**.
6. После последнего хода команда выбирает один ответ из вариантов для каждого из четырёх вопросов. Проверка человеком-ведущим, не свободный текст.
7. Оценка: `+2` за правильный ответ, `−1` за каждую раскрытую `red_herring`, `−3` за каждую карту, недостающую до **6** в закрытом сбросе.

### Главные требования к качеству дела

Прежде чем сочинять карточки, **построй скрытую для игроков истинную историю**: действующие лица, мотивации, точная хронология, реальная причина события, альтернативные гипотезы, связи между уликами. Только затем расщепи эту историю на разрозненные источники и создай карты.

- Разгадка должна быть **единственной и доказуемой**. Ключевые выводы нельзя делать лишь «по интуиции», мотиву или авторскому утверждению.
- Каждому из четырёх вопросов должно соответствовать минимум **две независимые опоры** в игровых картах. В JSON перечисли их ID в `evidence_card_ids`.
- Никакая одна обычная карта не должна одновременно раскрывать все ответы; важная информация распределена между несколькими свидетелями, датами, документами, предметами.
- Часть свидетелей может ошибаться или лгать, но игрок должен иметь способ обнаружить противоречие через другие доступные улики.
- Часы/даты/география/алиби/причинно-следственные связи должны быть согласованы. Создай внутреннюю хронологию и проверь её.
- Ложные следы должны выглядеть правдоподобно, а не быть заведомо бесполезными или абсурдными; в `logic_notes` укажи, почему они в действительности нерелевантны.
- Не менее шести карточек **разумно** отправить в сброс; для стандартного дела сделай **не менее восьми** `red_herring`.
- Нельзя строить решение на секретных `logic_notes`, которых игроки никогда не видят. При разумном выборе публикуемых карт дело должно быть раскрываемым.
- Придумай **оригинальные тексты**: протоколы, показания, объявления, письма, чеки, отчёты, карты местности и т.д. Стиль источника должен быть убедительным; помни, что это игра, а не инструкция к преступлению.
- Не допускай ошибок уровня: ложная разгадка, несколько одинаково верных вариантов, невозможно узнать правильный ответ, неразъяснённые совпадения, противоречивые цифры/имена.

### Объём стандартного сценария

- **1** вступление `intro` (2–5 абзацев, интригует, но не раскрывает решение).
- **1** стартовая открытая карточка `start_card`.
- **27** игровых карточек `play_cards`, с ID `clue-01` … `clue-27`.
- Среди них минимум **5** `essential`, минимум **8** `red_herring`, остальные `supporting`/`essential`.
- **4** финальных вопроса `questions`, с ID `q1` … `q4`; у каждого **4** текстовых варианта `a`, `b`, `c`, `d` и **ровно один** правильный.
- **1** подробная разгадка `solution` с хронологией ключевых событий.
- Ориентир: текст игровой карточки обычно 20–100 русских слов (не жёсткий технический лимит).
- Никаких обязательных изображений: текстового дела достаточно. Если реально создаёшь изображения и ZIP, можешь включить их в `assets/` и сослаться из `blocks`; иначе `assets: []` и только текстовые блоки. **Никогда не выдумывай существование файлов**.

### Строгая структура `case.json`

На верхнем уровне допускаются ТОЛЬКО поля:

`format`, `format_version`, `id`, `meta`, `intro`, `start_card`, `play_cards`, `questions`, `solution`, `scoring`, `assets`.

Обязательные значения:
- `"format": "detective-case"`
- `"format_version": "1.0.0"`
- `"id"`: уникальный slug латиницей, строчные буквы/цифры/дефисы.
- `"meta"`: `{ "title": строка, "author": строка, "summary": краткая без спойлеров строка, "difficulty": "medium", "estimated_minutes": 60, "language": "ru-RU", "min_players": 2, "max_players": 8, "original_work": true }`.
- `"intro"`: `{ "text": строка, "public_goal": строка }`.
- `"start_card"`: `{ "id": "start-01", "title": строка, "blocks": [ ... ] }`.
- `"play_cards"`: массив объектов `{ "id": "clue-01", "kind": "testimony" | "document" | "photo" | "object" | "report" | "other", "title": строка, "blocks": [ ... ], "role": "essential" | "supporting" | "red_herring", "logic_notes": строка, "supports_questions": ["q1", ...] }`.
- `"blocks"` — массив объектов. Текстовый блок: `{ "type": "text", "segments": [ { "text": "Обычный текст" }, { "text": "Можно произнести", "shareable": "highlight" }, { "text": "Фраза под скрепкой", "shareable": "clip" } ] }`. Поле `shareable` необязательное, только значения `highlight` / `clip`. Для изображения: `{ "type": "image", "asset_id": "photo-01", "caption": "Подпись" }` — использовать лишь при наличии реального файла в архиве.
- `"questions"`: массив `{ "id": "q1", "text": вопрос, "options": [ {"id":"a","text":вариант}, {"id":"b","text":вариант}, {"id":"c","text":вариант}, {"id":"d","text":вариант} ], "correct_option_id": "a" | "b" | "c" | "d", "explanation": конкретное объяснение, "evidence_card_ids": ["clue-03","clue-14", ...] }`.
- `"solution"`: `{ "full_story": подробная разгадка, "timeline": [ { "when": временная отметка, "event": описание события } ], "reveal_notes": пояснение о ложных следах и доказательной цепочке }`.
- `"scoring"`: `{ "points_per_correct": 2, "penalty_per_irrelevant_revealed": 1, "minimum_discards": 6, "penalty_per_missing_discard": 3 }`.
- `"assets"`: `[]`, если файлов нет; если есть — объекты `{ "id": строка, "path": "assets/name.webp", "mime": "image/webp" | "image/png" | "image/jpeg", "alt": строка }`.

Никаких других полей; ID карт уникальны; все ссылки на вопросы и карточки действительны; корректный ответ присутствует в вариантах. Все строки являются обычным текстом без HTML/JS, все двойные кавычки и переносы экранированы по JSON.

### Проверка перед выдачей

Проведи **внутреннюю редакторскую проверку**, не описывай длинные внутренние рассуждения пользователю. Проверь:

1. JSON синтаксически валиден, содержит **27** `play_cards`, **4** `questions`, нет `TODO` и недописанных частей.
2. Все 27 ID `clue-01`…`clue-27` существуют и уникальны, `start-01` отдельный.
3. Каждая из 4 опций вопроса различима, верна **только одна**; `correct_option_id` указывает на неё.
4. Для каждого вопроса есть минимум 2 реальные существенные карты, и правильный вариант логически выводится именно из них.
5. Хронология не противоречит карточкам; имена, времена и места написаны одинаково всюду.
6. Минимум 8 `red_herring`, минимум 5 `essential`, всем назначено честное объяснение значимости.
7. Нераскрытые карты не «подтекают» через публичное вступление; правильные ответы, служебные комментарии и решение хранятся только в закрытых полях.
8. Дело можно решить без доступа к служебным полям `role`, `logic_notes`, `supports_questions` и ответам.
9. В `assets` нет ссылок на несуществующие файлы и не нужны внешние сайты для решения.
10. При подозрении на логическую двусмысленность **перепиши проблему**, а не заявляй, что дело готово.

### Формат ответа

**Если умеешь создавать файлы:** создай `case.json` в UTF-8, при наличии реально сгенерированных картинок добавь `assets/`, упакуй в ZIP и назови `<id>.detective`. Дай готовый файл и короткую справку (название, число карт и вопросов). Не раскрывай разгадку в этой справке.

**Если умеешь только печатать текст:** выдай **один полный, валидный JSON** в блоке `json`, без пояснений внутри JSON. Не разбивай результат на «часть 1/часть 2», не используй `...`. Перед JSON разрешены ровно две строки с названием и количеством игровых карт, после JSON — одна короткая фраза о том, что файл нужно сохранить как `case.json` и упаковать в ZIP с расширением `.detective`.

Сейчас создай такое дело целиком.
