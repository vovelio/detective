# GAME_RULES — игровая механика MVP

Статус: согласованная механика на основе кооперативной карточной «Элементарно!» с описанными цифровыми адаптациями. Источник для сверки: https://tesera.ru/images/items/1707877/Rules-elementarno-smert-arkheologa-rus.pdf

## 1. Цель

Общими усилиями восстановить цепочку событий и правильно ответить на вопросы дела. Необходимо отсеять ложные и несущественные сведения, не потеряв ключевые улики. Все игроки действуют одной командой.

## 2. Термины

- **Стартовая карточка**: общая и открытая с начала, не раздаётся и не сбрасывается.
- **Игровая карточка**: находится в колоде, личной руке, на общем столе или в закрытом сбросе.
- **Рука**: приватные карты, текст виден только владельцу.
- **Раскрытие**: разыграть карту из руки лицом вверх на общий стол.
- **Сброс**: разыграть карту из руки в закрытый сброс. После сброса она недоступна для просмотра до завершающей стадии, даже её бывшему владельцу.
- **Разрешённые фрагменты**: специально помеченные автором слова/фрагменты, которые разрешается озвучивать до раскрытия карты.

## 3. Подготовка

1. Ведущий выбирает дело в лобби и запускает игру.
2. Всем показываются вступление и стартовая открытая карта.
3. Игровые карты перемешиваются **на сервере** случайным образом.
4. При двух участниках каждому выдаётся по 3 карты; при 3–8 — по 2 карты.
5. Остальные остаются в закрытой колоде. Порядок ходов случайный, один раз на партию, затем циклический.
6. Стартовая карта уже размещена на общем столе.

## 4. Основной цикл

Активный игрок должен выбрать **ровно одну** карту из своей руки и выполнить **одно** действие:

- **Раскрыть**: перетащить на общий стол. Во время перетаскивания локальный «призрак» видит только владелец; другим клиентам он не отправляется (уточнение UI_SPEC_FINAL этапа 5). При включённом подтверждении действие фиксируется после `Подтвердить`; если подтверждение отключено — после отпускания карты. После фиксации все получают полный текст карты; она остаётся открытой и может свободно перемещаться по доске.
- **Сбросить**: перетащить карту в компактную зону сброса размером примерно с карту. **Подтверждение сброса обязательно**, даже если подтверждение публикации отключено. Сброс закрытый; никто не видит содержимое во время расследования.

После успешного серверного подтверждения действия:

1. Карта атомарно перемещается из руки в общую зону или сброс;
2. Игрок автоматически получает 1 карту из колоды, если там есть карты;
3. Ход автоматически переходит следующему участнику в зафиксированном порядке.

При отмене, сетевом отказе или неуспешном действии ход **не** передаётся. Кнопки `Завершить ход` нет. Повтор действия с тем же `client_action_id` не может повторно сыграть карту.

Если у следующего участника нет карт, очередь пропускает его. Когда колода и все руки опустели, игра автоматически переходит к обсуждению.

## 5. Обмен сведениями

- Разрешено свободно обсуждать опубликованные общие карты и собственные гипотезы.
- Сведения из **нераскрытой** карты нельзя цитировать/пересказывать, кроме фрагментов, явно помеченных `shareable` (выделение или пометка-«скрепка»).
- Сведения со сброшенных карт не показываются системой во время игры. После завершения разыгрывания всех карт их можно обсуждать **по памяти**, но не возвращать на стол как открытые игровые улики.
- UI может показывать владельцу метку «Можно произнести» на разрешённых фрагментах, но не публикует их автоматически.

## 6. Завершение

Состояния: `LOBBY -> INTRO -> PLAYING -> DISCUSSION -> ANSWERING -> REVIEW -> RESULTS -> FINISHED`.

- `LOBBY`: запуск доступен ведущему при 2–8 участниках и валидном выбранном деле.
- `INTRO`: участники читают завязку; ведущий начинает игру.
- `PLAYING`: ходовые действия, разрешённые операции общего стола.
- `DISCUSSION`: все игровые карты разыграны; обсуждение по памяти и опубликованным данным. Любой игрок предлагает перейти к ответам, ведущий подтверждает предложение.
- `ANSWERING`: единый командный набор; для каждого вопроса выбирается один из вариантов сценария, свободного текста нет. Ведущий подтверждает окончательные командные ответы.
- `REVIEW`: ответы заблокированы; только ведущий получает ключ (`correct_option_id`, `explanation`, `evidence_card_ids`), без полной разгадки и ролей карт. Ведущий **вручную** отмечает ответы правильными/неправильными после фиксации выбора и по предоставленному автором ключу; итоговый счёт рассчитывает сервер.
- `RESULTS`: команда видит разгадку, вопросы/ответы, счёт и штрафы.
- `FINISHED`: переход из RESULTS по явному действию ведущего; партия зафиксирована как завершённая, игровые действия запрещены, просмотр результата разрешён.

Запрещены переходы вперёд в обход условий фазы; действия стола после завершения не меняют игровой результат.

## 7. Оценка

По правилам базового режима:

`score = 2 * correct_answers - irrelevant_revealed_count - 3 * max(0, min_discard - discarded_count)`

По умолчанию `min_discard = 6`; правильный ответ = `+2`; раскрытая нерелевантная карточка = `−1`; каждая недостающая до шести сброшенная карточка = `−3`. Вступительная карта не участвует в штрафах. За сброшенную важную карту отдельного числового штрафа нет, однако это может повлиять на возможность правильного ответа.

Семантика релевантности хранится **на сервере** (`role = red_herring` означает нерелевантную), никогда не передаётся активным игрокам. Результат может быть отрицательным. Число вопросов сценария настраиваемое; для стандартного дела рекомендованы четыре.

## 8. Серверные инварианты

- Карту из руки может сыграть только её владелец в свой ход.
- Карта бывает ровно в одном месте: колода, рука, доска или сброс.
- Один подтверждённый ход перемещает ровно одну карту; добор/смена хода атомарны.
- Порядок колоды и правильные ответы секретны.
- Заявка на завершение не даёт возможности раньше времени посмотреть ответы.
- При дисконнекте ход остаётся за участником; его возвращение сохраняет руку и место в очереди.
- Любое изменение проверяется сервером, а не только кнопками в интерфейсе.

До REVIEW ключ недоступен всем, включая ведущего. Разгадка доступна всем только в RESULTS/FINISHED. Временный дисконнект не меняет ведущего; ручная и автоматическая передача роли не входят в текущую реализацию.
