# UI_SPEC — интерфейс MVP

Историческая спецификация. Актуальный приоритет — UI_SPEC_FINAL.md, включая явные
уточнения владельца этапа 5. При расхождении компоновки/стрелок/призрака используйте FINAL.

## 1. Общие принципы

- Desktop-first, адаптация под планшеты; на телефонах должен быть как минимум доступен просмотр карт и участие в ходах, без обещания полноценного рисования как на desktop.
- Нейтральная аккуратная визуальная система; главное — читаемость карт и пространство стола.
- UI-панели **закреплены поверх** бесконечного игрового поля. Движение/масштабирование поля не должны сдвигать HUD.
- Все публикации, сбросы и изменения состояния имеют явное визуальное подтверждение или корректную обратную связь об ошибке.

## 2. Главная

Простой экран: название игры, `Создать комнату`, `Присоединиться`, поле для ссылки/кода комнаты, поле никнейма. Вход без регистрации. Никнейм длиной **2–20 символов** после удаления крайних пробелов; запрет пустой строки, управляющих символов. Совпадающие никнеймы в комнате не допускаются (технический default).

## 3. Лобби

- Список игроков и ведущий (создатель комнаты), видимость статуса подключения.
- Пригласительная ссылка с копированием.
- Выбор встроенного детективного дела из списка.
- Обязательная кнопка **«Добавить свою игру»**: выбор локального `.detective`, валидация, понятные сообщения об ошибках, выбор после успешного импорта.
- Только ведущий запускает. Начать можно при 2–8 игроках и валидном деле.
- После старта новые пользователи не присоединяются к партии; возвращение действующих участников разрешено.

## 4. Игровой экран

### Слои

1. Общая бесконечная доска (зум, панорамирование, открытые карты, рисунки, стрелки, заметки).
2. Указатели других участников и временные жесты перемещения.
3. Закреплённый HUD поверх доски.
4. Модальные подтверждения; не зависят от зума доски.

### Утверждённое расположение

- **Слева:** компактный список игроков со статусами.
- **Сверху:** компактная панель инструментов (выбор/рука, карандаш, ластик, стрелка, заметка; зум, «К центру»).
- **Справа:** фиксированная зона индикатора текущего хода и компактный сброс размером с карту.
- **Снизу:** личная рука — карты сразу открыты владельцу, горизонтальная лента. Неактивный участник может читать свою руку, но не может разыгрывать её.
- **Центр:** общее бесконечное пространство в духе Miro. Открытая стартовая карта видна всем с начала.

### Публикация и сброс

- Перетаскивание своей карты с нижней панели на доску до подтверждения рисует «призрак» только локально владельцу; другим клиентам не отправляется.
- После отпускания включённое по умолчанию подтверждение: `Опубликовать`/`Отмена`. Пользователь может отключить **только** подтверждение публикации в своих настройках.
- Сброс через фиксированную зону справа; подтверждение всегда обязательно, отмена возвращает карту в руку, ход остаётся прежним.
- После подтверждённого действия ход передаётся автоматически; отдельной кнопки завершения хода нет.

### Стол и объекты

- Открытые карты можно перемещать, но их размеры **фиксированы**: масштабируется сама камера доски, не индивидуальная карта.
- Указатели/курсоры других участников видны, но их координаты временные; их не нужно хранить в БД.
- Рисование — свободные линии, ластик — удаление созданных линий, стрелки могут быть привязаны к картам, текстовые заметки — краткие.
- Все завершённые изменения объектов рассылаются через WebSocket и сохраняются. В состоянии БД только завершённые изменения; частые промежуточные движения можно передавать как эфемерные.
- Кнопка **«К центру»** переводит камеру к стартовому расположению общих карт. Положение камеры — локальная настройка клиента, не общий объект.
- Группировка карточек и индивидуальный resize отсутствуют в MVP.

## 5. Обсуждение и ответы

- Когда закончились все руки и колода, подсказка о завершении разыгрывания; далее можно обсуждать уже открытые сведения.
- Любой участник нажимает `Предложить завершить расследование`; ведущий подтверждает переход.
- Экран вопросов содержит **варианты выбора из сценария**, а не текстовые поля. У команды один общий набор ответов.
- Текущие выбранные ответы синхронизируются; после блокировки ведущим редактирование недоступно.
- В REVIEW ведущий вручную отмечает правильность каждого зафиксированного ответа; ключ доступен только ведущему после фиксации ответов; остальным участникам — только в RESULTS. Полная разгадка до RESULTS недоступна всем.
- Экран результатов: ответы, разгадка, правильные/ложные улики, формула и итоговый счёт; возможность вернуться в главное меню; ведущий явно завершает партию (RESULTS → FINISHED), после чего доступен только просмотр.

## 6. Ошибки/пустые состояния

- При временной потере связи показывать `Переподключение…`; не дублировать карты/ходы.
- При ошибке отправки показывать короткую причину; не менять локально подтверждённое состояние до подтверждения сервера.
- При восстановлении из cookie клиент запрашивает актуальный снимок.
- При отсутствии выбранного дела или недостатке игроков кнопка `Начать` неактивна с объяснением.
- Ошибки валидации `.detective` показывать с конкретным JSON-путём и объяснением.

Передача роли ведущего (ручная или автоматическая) пока отсутствует. При временном отключении его роль сохраняется.
