# ACCEPTANCE_TESTS — что значит «MVP готов»

**Единственный окончательный продуктовый критерий:** команда друзей **полностью сыграла расследование на настоящем сервере**, от создания комнаты до раскрытия результата, без вмешательства разработчика и без критических дефектов. Автоматические тесты — необходимый допуск к испытанию, но не замена партии.

## 1. Автоматическая приёмка до тестовой партии

| ID | Что проверить | Ожидаемый результат |
| --- | --- | --- |
| A01 | Валидный `.detective` импортируется | дело доступно ведущему |
| A02 | Невалидный JSON, неверные ссылки, Zip Slip, oversized ZIP | безопасный отказ с диагностикой, без записи мусора |
| A03 | `game_engine` стартует для 2 и 8 игроков | руки 3/2, стартовая карта общая, колода корректна |
| A04 | Играется карта не своего владельца/не в свой ход | отказ без изменения ревизии |
| A05 | Повторяется тот же `client_action_id` | одна операция, один добор и один переход хода |
| A06 | Две конкурентные игровые команды с одинаковой ревизией | максимум одна меняет состояние; независимые операции доски проверяют версии своих объектов и могут обе сохраниться (уточнение этапа 5) |
| A07 | Отменена публикация/сброс | карта остаётся в руке, ход не меняется |
| A08 | Подтверждённый сброс | карта закрыта для всех, +1 сброс, добор и следующий ход |
| A09 | Публикация | всем только теперь открыт текст карты, запомнено положение |
| A10 | Попытка посмотреть чужую руку, колоду, `solution`, `role`, ключ | ни один REST/WS ответ их не раскрывает |
| A11 | Колода и все руки пусты | автоматический переход в DISCUSSION |
| A12 | Предложение завершения, вопросы, ручная проверка | переходы законны; ключ только ведущему в REVIEW, разгадка всем только в RESULTS |
| A13 | Счёт: 4 верных, 2 лишних открытых, 5 сброшенных | 8 − 2 − 3 = **3** очка |
| A14 | Явное завершение ведущим RESULTS → FINISHED и очистка соединений | игровые действия запрещены, итоги доступны, приватность не ломается |
| A15 | Неожиданное отключение и F5 в свой ход | возвращается тот же участник, карты и очередь сохранены |
| A16 | Рестарт FastAPI | из PostgreSQL восстанавливается актуальная партия и стол |
| A17 | События доски/рисунков в двух браузерах | сходимость состояния, нет дубликатов |
| A18 | Параллельные комнаты | действия из одной комнаты не затрагивают другую |
| A19 | Встроенный вариант ответа из сценария | нельзя отправить несуществующий option ID |
| A20 | Все assets из ZIP | не требуется внешняя сеть, файлы безопасно декодируются |

## 2. Настоящая партия с друзьями

Испытание проводится с 2–8 участниками на разных браузерах/устройствах, желательно с реальной голосовой связью вне сайта. Использовать **законченное оригинальное дело**, не `examples/demo-case.json`.

- [ ] Ведущий создал комнату, прислал ссылку; остальные вошли без аккаунтов.
- [ ] Никнеймы отображаются корректно, 2–20 символов; ведущий выбрал или импортировал сценарий.
- [ ] Вступление и стартовая карта понятны; 2–8 игроков корректно получили свои карты.
- [ ] Команда последовательно разыграла все карты: публикации и закрытые сбросы без нарушения очереди.
- [ ] На общем столе карты перемещались, участники пользовались заметками, стрелками и рисованием; изменения увидели остальные.
- [ ] Хотя бы один участник сделал F5 и отключился от сети; затем вернулся в свою руку и партию без потери прогресса.
- [ ] Ведущий или сервер был перезапущен в контролируемом техническом тесте **до** итоговой публичной проверки, и состояние восстановилось; в живую партию намеренно сервер не ронять без согласия игроков.
- [ ] Все игровые карты закончились, участники обсудили версию, один предложил завершение, ведущий подтвердил.
- [ ] Команда выбрала варианты на все вопросы; ведущий вручную зафиксировал правильность.
- [ ] Показана разгадка, корректные штрафы и суммарные очки.
- [ ] Ни один участник не получил скрытые карточки/ответы других из-за UI или сетевой ошибки.
- [ ] Игроки смогли понять, что делать, без подсказок разработчика.

## 3. Критические блокеры приёмки

Утеря партии или личной руки; дублирование хода; раскрытие скрытых данных; невозможность завершить расследование; систематическая рассинхронизация; неверный подсчёт; невозможность войти/вернуться; непригодный для игры сценарий; падение сервера, мешающее доиграть; необходимость вмешательства разработчика для основных действий.

Небольшие визуальные проблемы и косметические несовершенства допускаются, если не мешают нормальной игре; их фиксируют для следующих версий.

## 4. Итоговый акт

Записать дату, версию приложения/сценария, число участников, длительность, устройство/браузер, прошли ли до конца, найденные блокеры и решения. Только после успешного прохождения чеклиста ставить в `TASKS.md` отметку «MVP принят».


## Проверка импорта этапа 6

Для A01/A02/A18/A20 до живой приёмки проверять также:

- Ведущий в LOBBY импортирует .detective; обычный участник/посторонний/запущенная партия
  получают безопасный отказ. Origin/CSRF обязательны, JSON-лимиты других POST сохранены.
- ZIP Slip/симлинки/дубли/чрезмерная распаковка/повреждения/неверная версия/изображения
  отклоняются без сохранения доступного частичного дела и без отражения секретов.
- Повтор/конкурентная загрузка не повреждают архив; другое содержимое под прежним
  авторским ID не заменяет дело. Ошибки диска/БД не оставляют метаданных на недописанный
  файл; referenced SHA256-пакет никогда не удаляется при ошибке другого импорта.
- Комнатное дело отсутствует в глобальном каталоге и недоступно другой комнате.
- Потеря ответа после COMMIT разрешается обновлением каталога/повтором того же файла.
- Дело выбирается отдельно от импорта; запуск раздаёт карты один раз, чужие изображения
  закрыты. Перезапуск API сохраняет каталог/архив/партию/руку/доску.
- Настоящие два браузерных контекста проходят полную партию с загруженным делом
  до FINISHED, сохраняя восстановление и интерактивный стол этапа5.

Эти автоматические проверки не заменяют итоговую партию друзей на VPS.
