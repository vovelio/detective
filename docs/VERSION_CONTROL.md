# Git и версии проекта

Приватный репозиторий: https://github.com/vovelio/detective.
`main` хранит основную историю. Каждое законченное изменение сохраняем отдельным
коммитом с понятным описанием. Новые задачи выполняем в ветках `codex/<название>`;
перед слиянием проверяем изменения и результаты CI.

Первая контрольная точка — тег `baseline-2026-11-17`: состояние до начала ведения
истории. Это технический снимок, а не принятый MVP. Следующие проверенные выпуски
можно отмечать тегами `v0.1.0`, `v0.2.0` и далее; опубликованные теги не переносим.
Версия приложения не меняет `format_version` сценариев.

## Повседневная работа

```sh
git status
git switch main
git pull --ff-only
git switch -c codex/task-name
# Выполнить задачу и проверки из README.md.
git diff
git add <пути-к-файлам-задачи>
git diff --cached
git commit -m "Краткое описание законченного изменения"
git push -u origin codex/task-name
```

После push открываем pull request в `main`. CI запускается на push и pull request.
Зелёный CI не заменяет живую приёмку из `ACCEPTANCE_TESTS.md`.

## Посмотреть прежнюю версию

```sh
git log --oneline --decorate --graph --all
git tag --list
git diff baseline-2026-11-17..main --stat
```

Для запуска старой версии удобнее отдельная папка: текущие незакоммиченные изменения
остаются на месте.

```sh
git worktree add --detach ../detective-baseline baseline-2026-11-17
```

В этой папке заново устанавливаем зависимости по README.md. Для запуска используем
отдельную тестовую БД и хранилище: снимок кода не откатывает данные, cookie, архивы
дел, переменные окружения и миграции. Не подключаем старый код к живой БД.

Чтобы продолжить разработку от старой точки:

```sh
git switch -c codex/from-baseline baseline-2026-11-17
```

Перед переключением сохраняем текущую работу коммитом. Для отмены конкретного
изменения в общей истории используем `git revert <commit>` и обычный push.
`reset --hard` и force push для перехода между версиями не нужны.

## Что не сохраняется в Git

`.env` и другие локальные env-файлы, `.local/`, зависимости, сборки, резервные копии
и дампы исключены через `.gitignore`. Коммитим только шаблоны `.env.example` и
`.env.production.example` с демонстрационными значениями. Перед каждым коммитом
проверяем список и содержимое добавленных файлов.
